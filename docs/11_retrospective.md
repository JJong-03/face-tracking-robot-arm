# 프로젝트 회고

> 프로젝트를 마친 뒤 무엇이 잘 작동했고, 무엇이 어려웠으며, 다음에 무엇을 더 잘할 것인지를 정리한다.

## 회고 요약

가장 크게 배운 점은, 로봇팔 추적 시스템의 안정성을 끌어올리기 위해서는 하드웨어와 소프트웨어를 따로 볼 수 없다는 것이었다. 초기에는 소프트웨어 보정으로 흔들림을 해결하려 했지만 한계가 분명했고, 하드웨어 교체만으로도 문제가 끝나지 않았다. 결국 제어 로직 재설계와 하드웨어 보강을 함께 진행했을 때 비로소 최종 성능 목표에 도달할 수 있었다.

또 하나의 핵심 학습은 정량 지표의 중요성이었다. 성능을 수치로 정의하고, 그 지표를 반복 수정하는 과정이 프로젝트 품질을 실제로 끌어올렸다.

## 잘된 점

### 정량 지표를 실제 개선 도구로 사용

FRT·IFR·ICR 3종 지표를 2학기 초에 수립한 뒤, 교수 피드백을 반영해 3차 이상 수정했다. 속도 조건 명시, MOS 기반 주관 지표 폐기, 프레임 기반 정량화, 측정 절차 표준화가 이뤄졌고, 최종 발표에서 3종 모두 충족됐다.

### 문제를 하드웨어와 소프트웨어 양쪽에서 접근

ICR이 약 `60%`에 머물며 소프트웨어 보정의 한계가 드러난 뒤, 고토크 서보모터·1축 짐벌·고프레임 카메라 도입과 제어 알고리즘 재설계를 함께 진행했다.

### 제어 리디자인을 끝까지 밀고 감

10주차에 OneEuro 필터, 비례제어, Soft Deadzone, EMA, Adaptive Alpha를 도입한 제어 리디자인 결과, DNN 좌표 노이즈 `±5px → ±1px`, 제어 갱신률 `12~25Hz → 66~100Hz`로 개선됐다.

### FHD 실시간 처리 확보

ROI 캐싱, 스레드 분리, Adaptive skip, FP16 최적화를 적용해 FHD 40프레임 이상 동작을 확보했다.

### 외부 평가까지 연결

정보기술대학장 장려상을 수상했다.

## 어려웠던 점

### 소프트웨어 보정의 구조적 한계

데드존, 타이머, 보정 로직 조정으로 해결하려 했지만, MG996R의 기계적 진동 앞에서 한계가 명확했다.

### 하드웨어 교체가 새 문제를 만든 점

고토크 디지털 서보로 교체 후 오히려 1틱 단위 미세 진동이 더 심해졌다. 기존 아날로그 서보 기준 PWM 값을 그대로 적용한 것이 원인이었다.

### FHD 전환 병목

해상도를 높이는 것이 단순 화질 문제가 아니라 시스템 구조를 다시 보게 만드는 계기였다. 단일 스레드 구조만으로는 동작하지 않았다.

### 지표를 처음부터 잘 정의하는 어려움

측정 속도, 이동 경로, 반복 횟수, 환경 표준화까지 함께 정의해야 의미가 생겼고, 이 점을 실제 실패를 거치며 배웠다.

## 기술적으로 배운 점

- **하드웨어 변경은 제어 파라미터와 함께 봐야 한다**: 같은 PWM 입력이라도 서보모터의 응답 특성이 달라지면 시스템 전체 거동이 달라진다.
- **필터와 제어 알고리즘은 조합으로 봐야 한다**: Kalman, OneEuro, 비례제어, Deadzone, EMA는 어떤 노이즈를 줄이기 위해 어떤 순서와 강도로 조합할지가 중요했다.
- **실시간 시스템은 병목을 분해해서 봐야 한다**: 검출 주기, 추적 보정, 렌더링, 통신, 해상도를 따로 떼어 보고 우선순위를 정해야 개선이 가능했다.
- **"동작함"과 "안정적으로 동작함"은 다른 문제다**: 제어 파이프라인 자체는 만들 수 있어도, 명령 적체·지연·과도 반응·떨림을 줄이는 안정화가 실제로 중요한 부분이었다.

## 협업에서 배운 점

- 팀장 역할에서 기술 기여와 운영은 분리되지 않았다. 기술적 병목을 이해해야 일정도 조정할 수 있었다.
- 2학기 시작 시 음성/조명 기능을 과감히 제외하고 핵심 품질에 집중한 판단이 최종 결과에 기여했다.
- 주간 기록이 남아 있는 구간은 의사결정과 개선 흐름을 복원하기 쉬웠지만, 기록이 없는 1학기 후반은 발표자료에 의존할 수밖에 없었다.

## 아쉬운 점

- **초기 하드웨어 선정에서 정량 목표와의 연결이 약했다**: MG996R 선택 시 정지 안정성 목표와의 정합성을 더 앞단에서 검토했어야 했다.
- **최종 측정 로그를 더 체계적으로 남기지 못했다**: 자동 로그 구조를 더 일찍 만들었어야 했다.
- **변경 요인의 기여도를 분리하지 못했다**: 모터 교체, 짐벌 추가, 제어 재설계가 가까운 시기에 함께 진행돼 각각의 기여도를 독립적으로 설명하기 어렵다.

## 다음 프로젝트에서 바꾸고 싶은 점

- 정량 지표를 구현 후반이 아니라 초기에 같이 설계하기
- 측정 환경, 반복 횟수, 파라미터 스냅샷을 자동 로그로 남기기
- 하드웨어 교체 전후를 같은 조건에서 단계적으로 비교하기
- 발표 직전에도 최소 단위의 주간 기록을 유지하기
